# 05 — Menu bar indicator (SwiftBar)

SwiftBar plugin `menubar/anthropic-tunnel.5s.py` (Python 3, stdlib only; the
same file also runs under Argos on Ubuntu GNOME, see spec/08 and
`menubar/install-linux.sh`; on macOS nothing below changed on 2026-10-29),
refresh 5 s, installed by `menubar/install.sh` (no sudo) into SwiftBar's
plugin folder (`~/Documents/SwiftBar/Plugins`, the operator's existing choice).
Reads sing-box Clash API on 127.0.0.1:9090 with the secret from
`private/secrets/clash-api.secret`. State between ticks in
`~/Library/Application Support/anthropic-tunnel-menubar/state.json`.
All text English.

**SwiftBar version (2026-10-28):** use 2.1.1 from the Homebrew cask. A
manually installed 2.0.1 crashed at launch on a current macOS (SIGTRAP in
makeProcessSource at didFinishLaunching). 2.1.1 ignored the old
PluginDirectory preference until the folder was chosen again via "Change
Plugin Folder…". Make SwiftBar a login item.

## States and colours

Colours: Apple system colours as light,dark pairs (green #34c759/#30d158,
blue for ACTIVE #007aff/#0a84ff, red #ff3b30/#ff453a, grey #8e8e93/#98989d),
title text bold 12 pt. History: yellow, orange, bright blue and dark tones
were each rejected by the operator on 2026-10-28 as unreadable on the menu bar;
system colours are the ones macOS itself uses on the bar.

| State | Colour | Condition |
|---|---|---|
| CONNECTED, idle | green | daemon running, selected outbound healthy (delay test to api.anthropic.com via tunnel OK), no Anthropic bytes in the last 10 s |
| ACTIVE | blue (spec said yellow) | as green, and bytes moved through the `anthropic` outbound in the last 10 s (from `/connections` upload/download deltas) |
| DOWN (kill switch engaged) | red | daemon running but selected outbound unhealthy, or server TCP/UDP check fails; Anthropic traffic is being refused |
| DISABLED by user | grey | launchd daemon not loaded; traffic goes direct knowingly |
| UNKNOWN | grey with "?" | API unreachable while daemon reports running (transient) |

Yellow uses a 10 s window so it does not flicker. RED needs two consecutive
failed probes (`RED_AFTER_FAILURES = 2`); after a single failure the last good
state is kept with a "·" after the latency. Reason: the first live run showed a
genuine 10 s hiccup on the link that would otherwise flap red/green.

The probe is sing-box's own delay test (`/proxies/<selected>/delay` against
https://api.anthropic.com/v1/models, 4 s timeout), so "connected" means
"Anthropic answers through the tunnel", not just "WireGuard handshake".

## Icon

Three concentric circles as a base64 PNG embedded in the plugin, one per
state colour, generated by `menubar/make_icons.py` (pure Python PNG writer,
18x18 px, 8x supersampled). Reason: SwiftBar 2.1.1 ignored `sfcolor` on
`sfimage=target`, so the SF Symbol stayed black and only the text carried the
colour (found 2026-10-28). Same shape in all states; only colour changes.
Regenerate after changing COLS in make_icons.py.

## Title text (next to icon)

Narrow on purpose (menu bar width is limited, see `private/notes.md`): `✓` when idle (an empty title makes SwiftBar drop the item, found 2026-10-28),
`↓25B`-style single rate when ACTIVE, `·` after one failed probe, `DOWN`,
`OFF`, `?`. Latency and both rates live in the dropdown.

## Dropdown menu (left click; SwiftBar has one menu)

Items are enabled/disabled by current state:

- **Status line**: `Connected via WireGuard · 42 ms · up 3h 12m`
- **Connect** (enabled only when DISABLED)
- **Disconnect** (enabled only when CONNECTED/ACTIVE/DOWN) → runs tunnel-down.sh
- **Restart tunnel**
- **Transport ▸** WireGuard / VLESS (radio, switches the selector via API;
  only transports present in config are shown)
- **Stats ▸** session upload / download, active Anthropic connections (list of
  hosts), packets if the API exposes them (verified, not assumed)
- **Open log**, **Copy diagnostics**
- **Server reachable: yes/no**, **Anthropic reachable via tunnel: yes/no**
- **Quit indicator**

Actions that need root (connect/disconnect) go through a small helper
installed with the daemon that uses `sudo` with a limited `sudoers` entry for
exactly those two scripts; recorded in decisions.md.

## Notifications

On state change only (RED↔GREEN/YELLOW, GREY↔others): one macOS notification
via `osascript display notification`, English, e.g. "Anthropic tunnel DOWN /
Anthropic traffic is blocked (kill switch)".
